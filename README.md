# ActiveAdminTheme

A dense desktop theme and a set of shared components for [ActiveAdmin](https://github.com/activeadmin/activeadmin) 4.

ActiveAdmin 4 keeps its menu in a left sidebar and gives breadcrumbs and titles a lot of room. That works on mobile but wastes width on a laptop with a large table and many filters. This theme keeps the compact desktop layout of theme 3 and keeps ActiveAdmin 4's mobile support:

- **Desktop** (768px and wider): a horizontal top menu, compact breadcrumbs and title, filters left of the table (collapsible).
- **Mobile** (narrower than 768px): the menu opens in a drawer, filters sit above the table, forms and show pages use the full width.
- Index tables scroll sideways when they are wider than the screen, and cells stay on one line.
- Theme 3 colors, density, and typography on top of ActiveAdmin 4's own dark mode.

Theme 4 needs ActiveAdmin 4 (`>= 4.0.0.beta23`) and Ruby 3.3 or newer. For ActiveAdmin 3, use theme 3.x (branch `3.x`). See [docs/migrating-from-v3.md](docs/migrating-from-v3.md).

## Installation

Add the gem and install it:

```ruby
gem "active_admin_theme"
```

The gem requires `active_admin` first, so its views and partials win over ActiveAdmin's own. Do not reorder that.

### CSS

ActiveAdmin 4 builds its CSS with Tailwind CSS 4. Your Tailwind entry file (generated by `rails g active_admin:assets`, usually `app/assets/stylesheets/active_admin.css`) must import the theme CSS after Tailwind. Pick one route.

**From the installed gem.** The gem's location differs between machines (a laptop, a Docker image, CI), so the path must not be committed. The task writes it into a generated file next to your entry file, and the entry file only imports that file by a fixed name:

```sh
bin/rails active_admin_theme:css
```

The entry file gets this block, which is the same on every machine, so commit it:

```css
@import "tailwindcss";
@config "../../../tailwind-active_admin.config.js";

/* active_admin_theme:begin */
@import "./active_admin_theme.generated.css";
/* active_admin_theme:end */
```

The task writes `active_admin_theme.generated.css`, which holds the machine-specific path. Add it to `.gitignore`:

```
/app/assets/stylesheets/active_admin_theme.generated.css
```

Run the task before every Tailwind build, because the generated file does not exist on a fresh checkout and its path changes when the gem upgrades. For example, in the build script that runs Tailwind:

```sh
bin/rails active_admin_theme:css && npx tailwindcss -i app/assets/stylesheets/active_admin.css -o app/assets/builds/active_admin.css
```

If that is awkward for your build, use the npm route.

**From the npm package.** This avoids a machine-specific path and a build step, and fits hosts that already install `@activeadmin/activeadmin` from npm:

```sh
npm install @activeadmin-plugins/active_admin_theme
```

```css
@import "tailwindcss";
@config "../../../tailwind-active_admin.config.js";
@import "@activeadmin-plugins/active_admin_theme/css";
```

Keep the npm package and the gem on the same version.

Tailwind only generates the classes it finds in files it scans. In `tailwind-active_admin.config.js`, add the gem's files to `content`:

```js
const themePath = execSync('bundle show active_admin_theme', { encoding: 'utf-8' }).trim().split(/\r?\n/).pop();

export default {
  content: [
    // ActiveAdmin's entries stay as they are
    `${themePath}/app/**/*.{arb,erb,html,rb,js}`,
    `${themePath}/lib/**/*.rb`,
    // ...
  ],
  // ...
}
```

### JavaScript

ActiveAdmin 4 renders its own import map, `ActiveAdmin.importmap`, not the import map in your `config/importmap.rb`. A `pin` in your own `config/importmap.rb` loads nothing on ActiveAdmin pages.

The theme's engine pins its modules into `ActiveAdmin.importmap`, so importmap hosts need no setup. To load one of your own scripts on ActiveAdmin pages, pin it into the same map, for example in `config/initializers/active_admin.rb`:

```ruby
ActiveAdmin.importmap.pin "my_admin_script", to: "my_admin_script.js"
```

ActiveAdmin pages import the modules listed in `ActiveAdminTheme.javascripts`. With an ActiveAdmin that has the `javascript_modules` setting ([activeadmin/activeadmin#9148](https://github.com/activeadmin/activeadmin/pull/9148)), the theme adds them to that setting after your initializers run. With an older ActiveAdmin, the theme's own `_html_head` imports them. The default list is:

```ruby
%w[
  active_admin_theme/layout
  active_admin_theme/server_clock
  active_admin_theme/table_crisscross
]
```

Change the list in an initializer to load fewer scripts or to add the optional ones:

```ruby
ActiveAdminTheme.javascripts -= %w[active_admin_theme/table_crisscross]
ActiveAdminTheme.javascripts += %w[active_admin_theme/secret_reveal]
```

**jsbundling hosts.** The npm package exports each module (`@activeadmin-plugins/active_admin_theme/layout`, `.../server_clock`, and so on). Import the ones you want from your `active_admin` entry file, and override `app/views/active_admin/_html_head.html.erb` to load your bundle.

## Overriding

A host partial with the same path overrides the theme's. Copy the partial from the gem into your app's `app/views/active_admin/` and edit it. The theme's partials are:

- `_header_leading`: the menu button and the site title.
- `_header_navigation`: the top menu.
- `_main_navigation`: the mobile drawer menu.
- `_header_actions`: the server clock, the dark mode switch, the current user, and the logout icon.
- `_page_heading`, `_breadcrumbs`, `_page_title`: the sidebar toggle, the breadcrumbs, and the page title.
- `_page_content`: the grid that holds the sidebar and the page.
- `_sidebar`.

ActiveAdmin renders these partials from its own layout once it has the layout hooks ([activeadmin/activeadmin#9149](https://github.com/activeadmin/activeadmin/pull/9149) to [#9152](https://github.com/activeadmin/activeadmin/pull/9152)). Until then, the theme also ships copies of the layout, `_site_header`, `_page_header`, and `_html_head` in `app/views_compat` that render the same partials. The engine adds that directory to the view paths only when the installed ActiveAdmin lacks the hooks, so override the small partials above rather than those copies.

A host Arbre component with the same builder method name replaces the theme's, as long as it loads after the theme's. Components in `app/admin_components` (or any file loaded in a `to_prepare` block) do.

## Colors

All colors are CSS custom properties with a light value on `:root` and a dark value under `.dark`. Override any of them in your own CSS:

```css
:root {
  --aat-header-bg: #1b3a57;
  --aat-button: #1f6f4a;
}
.dark {
  --aat-surface: #20242b;
}
```

| Property | Used for |
| --- | --- |
| `--aat-page-bg`, `--aat-surface`, `--aat-surface-2`, `--aat-surface-hover`, `--aat-selected-row` | Page, panels, table headers, hover, selected rows |
| `--aat-text`, `--aat-text-muted`, `--aat-border` | Text and borders |
| `--aat-input-bg`, `--aat-input-border` | Form controls |
| `--aat-accent`, `--aat-link` | Accent and links |
| `--aat-button`, `--aat-button-text` | Buttons and action items |
| `--aat-header-bg`, `--aat-header-text`, `--aat-menu-*` | Header and top menu |

## DSL

### `columns`

ActiveAdmin 4 removed `columns` and `column`. The theme restores them, with separate control for mobile and desktop.

```ruby
columns "1:3" do                 # desktop: 1/4 + 3/4; mobile: stacked
  column { ... }
  column { ... }
end

columns "1:1", mobile: "1:1" do  # side by side on mobile too
  ...
end

columns do                       # no ratio: equal widths, any number of columns
  ...
end
```

- The ratio string lists one weight per column. Pixel widths are not supported.
- On mobile, columns stack unless `mobile:` sets a ratio.
- A column has a minimum width of `--aat-col-min` (14rem). When the row has no room for it, the column moves to the next line instead of clipping its content.
- `column span: N` from ActiveAdmin 3 still works and counts as the column's weight.

### `tabs`

```ruby
tabs do
  tab("Details") { ... }
  tab("History", id: "history") { ... }
end
```

Tabs use Flowbite's tabs, which ActiveAdmin already loads.

### `panel`

ActiveAdmin 4 still has `panel`, but no longer wraps sidebar content or the show page's `attributes_table` in one. The theme wraps both again: sidebar sections in a panel titled with the section name, and `attributes_table` on a show page in a "Model Details" panel. `Panel#header_action` is not restored.

## Components

Every component is opt-in: nothing changes for an app that does not call it or load its script. In a `content do` block, wrap the helpers that return strings (`with_tooltip`, `pre_wrap`) in `text_node`.

### `status_tag`

`ok`, `warning`, `error`, `info`, and `empty` have theme colors in light and dark mode. For any other value, define a CSS custom property named `--aat-status-<value>` in your CSS. For a one-off color, pass `color:` (a hex, named, `rgb()`, or `hsl()` color; anything else raises `ArgumentError`):

```ruby
status_tag "Shipped"                # uses --aat-status-shipped, if you define it
status_tag "Late", color: "#b91c1c"
```

### `truncate_text`

One line of text with an ellipsis and the full value in the `title` attribute:

```ruby
truncate_text(order.note, length: 40, max_width: "12rem")
```

### `with_tooltip`

A plain `title` hint by default. With `html: true`, the tooltip is sanitized HTML shown by ActiveAdmin's Flowbite tooltip. The HTML tooltip is positioned inside its container, so a wrapper with `overflow` (a scrolling table) can clip it.

```ruby
text_node with_tooltip("42", "Total orders")
text_node with_tooltip("42", "<b>Total</b> orders", html: true)
```

### `pre_wrap`

Preformatted text that wraps long lines:

```ruby
text_node pre_wrap(response.body)
```

### `secret_reveal`

A masked value that is fetched and shown on click. The URL must return `{"value": "..."}`. Needs the `active_admin_theme/secret_reveal` script.

```ruby
secret_reveal url: secret_admin_account_path(account), mask: "••••••••"
```

### `confirm_dialog`

A confirmation dialog with optional form fields, built on the Flowbite modal that ActiveAdmin uses for batch actions. It submits a real form with the CSRF token. Needs the `active_admin_theme/confirm_dialog` script for focus handling and field validation. Do not place it inside another form.

```ruby
confirm_dialog "Reject", title: "Reject order", message: "The buyer is notified.",
  url: reject_admin_order_path(order), method: :post,
  fields: [
    {name: :reason, label: "Reason", as: :text, required: true},
    {name: :kind, as: :select, collection: [["Fraud", "fraud"], ["Other", "other"]]},
    {name: :notify, label: "Notify the buyer", as: :boolean, value: true}
  ]
```

Field types are `:string`, `:text`, `:select`, and `:boolean`.

### Searchable select

A select built on [tom-select](https://tom-select.js.org) that searches over AJAX, loads more options as you scroll, and can depend on another select. It works in forms and filters, and on mobile. The gem vendors a pinned tom-select and pins it into `ActiveAdmin.importmap`; an app that does not load the script does not load tom-select. npm hosts add `tom-select` to their own dependencies. Add the script:

```ruby
ActiveAdminTheme.javascripts += %w[active_admin_theme/searchable_select]
```

If your app already defines its own `searchable_select_options` in an initializer, yours wins: the theme includes its version earlier.

Serve the options from the resource that holds them:

```ruby
ActiveAdmin.register Customer do
  searchable_select_options label: :name, search: :name_cont, per_page: 25
end
```

`searchable_select_options(name = :all, scope: nil, label: nil, search: nil, value: :id, order: nil, per_page: 25)` adds a collection action that returns `{results: [{id:, text:}], has_more: true}` for `?term=` and `?page=`. It applies the authorization adapter's read scope. Use the input in a form or a filter:

```ruby
f.input :customer, as: :searchable_select
f.input :city, as: :searchable_select, depends_on: :country_id, depends_placeholder: "Select a country first"
filter :customer, as: :searchable_select
```

A dependent select stays disabled until its parent has a value, and reloads when the parent changes. Other options: `url:`, `resource:`, `options_name:`, `placeholder:`, `depends_param:`.

## Optional scripts

| Script | Default | What it does |
| --- | --- | --- |
| `active_admin_theme/layout` | on | Collapsible sidebar |
| `active_admin_theme/server_clock` | on | Header clock |
| `active_admin_theme/table_crisscross` | on | Row and column highlight on a cell click |
| `active_admin_theme/confirm_dialog` | off | Focus and validation for `confirm_dialog` |
| `active_admin_theme/secret_reveal` | off | `secret_reveal` |
| `active_admin_theme/searchable_select` | off | Searchable select |

## Nested menus

ActiveAdmin 4 supports one submenu level and raises `TypeError` for a parent chain. The theme brings back the chain from ActiveAdmin 3, so menus can be as deep as you need:

```ruby
menu parent: ["Customer", "Referral Program"], priority: 30
```

In the top menu each deeper level flies out beside its item, and in the drawer it expands below its item. A top item is marked current when the page is anywhere below it.

## Header

The header shows the site title, the top menu, a server clock, the dark mode switch, the current user, and a logout icon. They come from the signed-in user (`current_active_admin_user?`) and `config.logout_link_path`. Without a current user the header shows only the title, the menu, and the dark mode switch. To change the header, override `_header_actions.html.erb`, `_header_leading.html.erb`, or `_header_navigation.html.erb`.

## Development

```sh
bundle install
bundle exec rake test                 # builds the dummy app's Tailwind CSS, runs smoke and browser tests (needs Chrome)
bundle exec ruby test/screenshot.rb   # PAGES, WIDTHS, MODES, OUT environment variables
```

`test/dummy` is an ActiveAdmin 4 app (importmap, propshaft, Tailwind through the npm CLI). Run `npm run build` in `test/dummy` to rebuild its CSS.

To run the tests against an unreleased ActiveAdmin, such as a branch with the layout hooks, point Bundler at it:

```sh
ACTIVEADMIN_PATH=../activeadmin bundle exec rake test
ACTIVEADMIN_BRANCH=extensible-layout bundle exec rake test   # from ACTIVEADMIN_REPO, default senid231/activeadmin
```

The theme replaces some of ActiveAdmin's own view files with its copies. `test/aa_overrides_test.rb` fails when the installed ActiveAdmin changes one of them. It records the originals for both modes, with and without the layout hooks, so run it against both. After you raise the ActiveAdmin version, diff each reported file against the theme's copy in `app/views` or `app/views_compat`, port what applies, then refresh the record:

```sh
UPDATE_AA_DIGESTS=1 bundle exec ruby test/aa_overrides_test.rb
```
